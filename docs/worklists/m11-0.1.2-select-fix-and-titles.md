# M11 0.1.2 Select Fix, Instance Titles, and Bell

Milestone Timing: Mirrors `M11` in [Project plan](../PLAN.md): start `2026-07-24` (begins when `M10` ends), target end `2026-09-04` (six-week window).

Status: Drafted, not yet started.

## Desired Outcome

TermiWeb should leave `M11` with a credible `0.1.2` patch release that unblocks the mobile selection bug, lands the instance-titles spec, introduces a real bell behavior, and verifies the residual state of the `0.1.1` mobile stabilization fixes so the issue tracker reflects what is actually shipped.

## 1. Work Breakdown

1. [ ] Fix the mobile Select-mode regression first because it is the release-blocker.
   1. [ ] Reproduce the issue from [#5](https://github.com/n8bar/TermiWeb/issues/5) on a real mobile browser and confirm the diagnosed cause (re-render during `pointerup` in `src/client/main.ts`).
   2. [ ] Decide between the two suggested fix directions captured in the issue (avoid destroying the active Select button during `renderModifierControls`, or add re-entrancy guarding to `bindControlButtonActivation`) and record the chosen direction in this worklist before implementing.
   3. [ ] Implement the chosen fix and confirm Select-mode opens, stays open, and can be exited only by an intentional tap.
   4. [ ] Verify the fix on a real mobile browser and a desktop browser, including modifier-button interaction since those buttons share the same activation path.

2. [ ] Verify and close out the `0.1.1` mobile stabilization issues that never closed after `M9` shipped.
   1. [ ] Re-test the behavior described in [#2 collapsed mobile instance controls](https://github.com/n8bar/TermiWeb/issues/2) against the shipped `0.1.1` UI on a real mobile browser.
   2. [ ] Re-test the behavior described in [#3 mobile keyboard text assistance](https://github.com/n8bar/TermiWeb/issues/3) against the shipped `0.1.1` UI on a real mobile browser with at least one mobile keyboard known to be aggressive about predictive text.
   3. [ ] For each issue, either close it with a comment pointing at the `M9` work that resolved it, or capture the residual behavior in the issue and add a remediation task to this worklist.
   4. [ ] If residual remediation tasks were added, implement and verify them before the release surface step.

3. [ ] Implement the instance-titles spec.
   1. [ ] Re-read [the instance-titles spec](../specs/instance-titles.md) and confirm no scope drift before implementation begins.
   2. [ ] Add the protocol and state changes: a shell-title field on `SessionSummary`, a `terminal/title` client event, and a server-side broadcast path for title changes. Apply the spec's length clamp and control-character stripping on the server before broadcasting.
   3. [ ] Wire `terminal.onTitleChange` on the client to send the `terminal/title` event for the active session.
   4. [ ] Change auto-naming to assign the lowest unused positive integer without ever renaming an existing instance as a side effect of another instance's lifecycle.
   5. [ ] Update the active-instance topbar heading and the sidebar list to render the precedence rule (shell title when present and non-empty, workspace default otherwise), and apply the ellipsis-with-tooltip overflow treatment in both places.
   6. [ ] Verify against every Acceptance Check listed in [the instance-titles spec](../specs/instance-titles.md). Capture any spec ambiguities discovered during implementation as edits to the spec before closing this item.

4. [ ] Specify and implement the terminal bell behavior.
   1. [ ] Draft the bell spec under `docs/specs/` covering audio versus visual default, mobile autoplay constraints, per-instance attention indicator behavior, and any user preference surface. Pause for user review of the draft spec before implementing (rule `1.16`).
   2. [ ] After the spec is approved, implement the chosen behavior and wire `terminal.onBell` accordingly.
   3. [ ] Verify against the bell spec's Acceptance Checks on desktop and mobile browsers, including the autoplay-unlock path if audio is in scope.
   4. [ ] Close [#6](https://github.com/n8bar/TermiWeb/issues/6) once the shipped behavior matches the approved spec.

5. [ ] Refresh the release surface and ship the `0.1.2` patch release.
   1. [ ] Update release notes, `package.json` / `package-lock.json`, the website download surface, README release wording, and any packaged-install copy that becomes stale once `0.1.2` lands.
   2. [ ] Confirm screenshots and public copy still represent the shipped UI; replace anything that became misleading because of the instance-titles or bell changes.
   3. [ ] Run the local release gate: `npm run typecheck`, `npm test`, `npm run build`, `npm run build:site`, `npm run package:release`.
   4. [ ] Publish the `0.1.2` GitHub release with the packaged artifact attached, confirm the GitHub Pages deploy succeeds, and close `M11`.

## 2. Verification Checklist

1. [ ] [#5](https://github.com/n8bar/TermiWeb/issues/5) is fixed on real mobile hardware and Select-mode is reliably usable.
2. [ ] [#2](https://github.com/n8bar/TermiWeb/issues/2) and [#3](https://github.com/n8bar/TermiWeb/issues/3) are closed with either a verification comment or a captured-and-fixed residual.
3. [ ] [#7 instance titles](https://github.com/n8bar/TermiWeb/issues/7) ships in `0.1.2` against the approved [instance-titles spec](../specs/instance-titles.md), including stable numbering and overflow display.
4. [ ] A bell spec exists, was reviewed by the user, and the shipped behavior matches it; [#6](https://github.com/n8bar/TermiWeb/issues/6) is closed.
5. [ ] The `0.1.2` local release gate passed and the release surface (release notes, README, site, packaged install copy) honestly describes what shipped.
6. [ ] Desktop browser behavior did not regress: instance create, select, resize, close, paste, modifier composition, selection/copy, and reconnect all still work.
