# M10 0.1.2 Select Fix, Windows Installer, Instance Titles, and Bell

Milestone Timing: Mirrors `M10` in [Project plan](../PLAN.md): start `2026-07-24`, target end `2026-09-25` (extended from `2026-09-04` by three weeks on `2026-08-06` to absorb the Windows-installer scope; renumbered from `M11` to `M10` on `2026-08-06` when the release was resequenced ahead of outreach).

Status: In progress since `2026-09-05`.

## Desired Outcome

TermiWeb should leave `M10` with a credible `0.1.2` patch release that unblocks the mobile selection bug, replaces the failure-prone zip setup with a real Windows installer whose auto-start path never asks for a Windows account password, lands the instance-titles spec, introduces a real bell behavior, and verifies the residual state of the `0.1.1` mobile stabilization fixes so the issue tracker reflects what is actually shipped.


1. [x] Fix the mobile Select-mode regression first because it is the release-blocker.
   1. [x] Reproduce the issue from [#5](https://github.com/n8bar/TermiWeb/issues/5) on a real mobile browser and confirm the diagnosed cause (re-render during `pointerup` in `src/client/main.ts`).
      Result (2026-09-05): reproduced on a real mobile browser. Code review did not confirm the re-render diagnosis; see the decision under `1.2`.
   2. [x] Decide between the two suggested fix directions captured in the issue (avoid destroying the active Select button during `renderModifierControls`, or add re-entrancy guarding to `bindControlButtonActivation`) and record the chosen direction in this worklist before implementing.
      Decision (2026-09-05): neither suggested direction. No second activation path exists: control buttons bind `pointerup` only, `pointerdown` is cancelled so the rebuilt button never receives focus, and the modifier buttons rebuild the tray inside the same `pointerup` path without failing. The actual close is the snapshot handler. Opening Select hides the terminal container and moves focus to a read-only textarea, which changes the mobile keyboard state; the resulting `visualViewport` resize schedules the coarse-pointer snapshot resync (220 ms plus 120 ms), and the `session/snapshot` handler in `src/client/main.ts` called `setSelectionMode(false)`. That reset dates from 2026-04-06, before the resync path existed (2026-04-10). Chosen direction: applying a snapshot never exits selection mode; while selecting, the snapshot refreshes the captured text instead of refocusing the live terminal. Selection mode still exits only through the Select button, the panel close button, the focus-terminal button, or an instance switch.
   3. [x] Implement the chosen fix and confirm Select-mode opens, stays open, and can be exited only by an intentional tap.
      Result (2026-09-05): fix implemented in the `session/snapshot` handler in `src/client/main.ts` with the `resolveSnapshotFollowUp` helper in `src/client/ui/terminalSnapshot.ts` and a regression test in `tests/client/terminal-snapshot.test.ts`; typecheck and tests pass; confirmed on device the same day.
   4. [x] Verify the fix on a real mobile browser and a desktop browser, including modifier-button interaction since those buttons share the same activation path.
      Result (2026-09-05): maintainer verified the fix on real mobile hardware.
      Note: enter Select with the mobile keyboard both open and closed, confirm the panel stays open in both cases, and confirm the terminal repaints correctly after exiting Select, since a snapshot can now land while the terminal container is hidden.

4. [ ] Implement the instance-titles spec.
   1. [x] Re-read [the instance-titles spec](../specs/instance-titles.md) and confirm no scope drift before implementation begins.
      Result (2026-09-06): re-read; no scope drift. Four ambiguities were resolved during implementation and written back into the spec: shell titles clear on process exit, legacy `Terminal N` keeps its number, duplicate persisted numbers move only the later tab, and the collapsed rail label never uses the shell title.
   2. [x] Add the protocol and state changes: a shell-title field on `SessionSummary`, a `terminal/title` client event, and a server-side broadcast path for title changes. Apply the spec's length clamp and control-character stripping on the server before broadcasting.
      Result (2026-09-06): `shellTitle` on `SessionSummary` (defaults to null), `terminal/title` client event, `sanitizeShellTitle` in `src/server/terminal/shell-title.ts`, `setShellTitle` on the session and manager, and dispatch in `src/server/http/app.ts`. Title changes ride the existing `session/list` broadcast.
   3. [x] Wire `terminal.onTitleChange` on the client to send the `terminal/title` event for the active session.
      Result (2026-09-06): wired in `src/client/main.ts` next to the `onData` handler.
   4. [x] Change auto-naming to assign the lowest unused positive integer without ever renaming an existing instance as a side effect of another instance's lifecycle.
      Result (2026-09-06): `normalizeWorkspaceTabs` in `src/server/workspace/workspace-state.ts` now keeps every parsable number and only assigns the lowest unused number to a tab whose number is missing or duplicated. Tests updated for the new expectations.
   5. [x] Update the active-instance topbar heading and the sidebar list to render the precedence rule (shell title when present and non-empty, workspace default otherwise), and apply the ellipsis-with-tooltip overflow treatment in both places.
      Result (2026-09-06): `resolveDisplayedSessionTitle` in `src/client/ui/sessionTitle.ts` drives the heading, sidebar entries, and their aria-labels; both surfaces set the native tooltip to the displayed title. The sidebar needed a `max-width` fix to ellipsize. Later the same day the maintainer asked for a mobile affordance since hover does not exist there: overflowing titles now scroll back and forth on coarse-pointer devices (`resolveTitleScroll` plus a CSS animation), and the spec was amended to require it.
   6. [ ] Verify against every Acceptance Check listed in [the instance-titles spec](../specs/instance-titles.md). Capture any spec ambiguities discovered during implementation as edits to the spec before closing this item.
      Partial (2026-09-06): the spec edits are done and the automated checks pass (sanitization, precedence, stable numbering, clear-on-exit, default-title filter, protocol). Workstation checks so far: setting a title updates the heading and sidebar, and a fresh instance surfaced pwsh's default console title, which led to the default-title filter. Still to run: empty title, close-the-middle-instance numbering, long-title overflow on desktop and mobile, two-client propagation, and server-restart behavior.
