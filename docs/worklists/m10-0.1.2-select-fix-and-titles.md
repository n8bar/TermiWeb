## Desired Outcome

TermiWeb should leave `M10` with a credible `0.1.2` patch release that unblocks the mobile selection bug, replaces the failure-prone zip setup with a real Windows installer whose auto-start path never asks for a Windows account password, lands the instance-titles spec, introduces a real bell behavior, and verifies the residual state of the `0.1.1` mobile stabilization fixes so the issue tracker reflects what is actually shipped.


1. [x] Fix the mobile Select-mode regression first because it is the release-blocker.
   1. [x] Reproduce the issue from [#5](https://github.com/n8bar/TermiWeb/issues/5) on a real mobile browser and confirm the diagnosed cause (re-render during `pointerup` in `src/client/main.ts`).
      Result (2026-09-05): reproduced on a real mobile browser. Code review did not confirm the re-render diagnosis; see the decision under `1.2`.
   2. [x] Decide between the two suggested fix directions captured in the issue (avoid destroying the active Select button during `renderModifierControls`, or add re-entrancy guarding to `bindControlButtonActivation`) and record the chosen direction in this worklist before implementing.
      Decision (2026-09-05): neither suggested direction. No second activation path exists: control buttons bind `pointerup` only, `pointerdown` is cancelled so the rebuilt button never receives focus, and the modifier buttons rebuild the tray inside the same `pointerup` path without failing. The actual close is the snapshot handler. Opening Select hides the terminal container and moves focus to a read-only textarea, which changes the mobile keyboard state; the resulting `visualViewport` resize schedules the coarse-pointer snapshot resync (220 ms plus 120 ms), and the `session/snapshot` handler in `src/client/main.ts` called `setSelectionMode(false)`. That reset dates from 2026-04-06, before the resync path existed (2026-04-10). Chosen direction: applying a snapshot never exits selection mode; while selecting, the snapshot refreshes the captured text instead of refocusing the live terminal. Selection mode still exits only through the Select button, the panel close button, the focus-terminal button, or an instance switch.
   3. [x] Implement the chosen fix and confirm Select-mode opens, stays open, and can be exited only by an intentional tap.
      Result (2026-09-05): fix implemented in the `session/snapshot` handler in `src/client/main.ts` with the `resolveSnapshotFollowUp` helper in `src/client/ui/terminalSnapshot.ts` and a regression test in `tests/client/terminal-snapshot.test.ts`; typecheck and tests pass; confirmed on device the same day.
   4. [x] Verify the fix on a real mobile browser and a desktop browser, including modifier-button interaction since those buttons share the same activation path.
      Result (2026-09-05): maintainer verified the fix on real mobile hardware.
      Note: enter Select with the mobile keyboard both open and closed, confirm the panel stays open in both cases, and confirm the terminal repaints correctly after exiting Select, since a snapshot can now land while the terminal container is hidden.
