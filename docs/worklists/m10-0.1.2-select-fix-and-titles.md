# M10 0.1.2 Select Fix, Windows Installer, Instance Titles, and Bell

Milestone Timing: Mirrors `M10` in [Project plan](../PLAN.md): start `2026-07-24`, target end `2026-09-25` (extended from `2026-09-04` by three weeks on `2026-08-06` to absorb the Windows-installer scope; renumbered from `M11` to `M10` on `2026-08-06` when the release was resequenced ahead of outreach).

Status: Drafted, not yet started.

## Desired Outcome

TermiWeb should leave `M10` with a credible `0.1.2` patch release that unblocks the mobile selection bug, replaces the failure-prone zip setup with a real Windows installer whose auto-start path never asks for a Windows account password, lands the instance-titles spec, introduces a real bell behavior, and verifies the residual state of the `0.1.1` mobile stabilization fixes so the issue tracker reflects what is actually shipped.


1. [ ] Fix the mobile Select-mode regression first because it is the release-blocker.
   1. [ ] Reproduce the issue from [#5](https://github.com/n8bar/TermiWeb/issues/5) on a real mobile browser and confirm the diagnosed cause (re-render during `pointerup` in `src/client/main.ts`).
   2. [ ] Decide between the two suggested fix directions captured in the issue (avoid destroying the active Select button during `renderModifierControls`, or add re-entrancy guarding to `bindControlButtonActivation`) and record the chosen direction in this worklist before implementing.
   3. [ ] Implement the chosen fix and confirm Select-mode opens, stays open, and can be exited only by an intentional tap.
   4. [ ] Verify the fix on a real mobile browser and a desktop browser, including modifier-button interaction since those buttons share the same activation path.

2. [ ] Verify and close out the `0.1.1` mobile stabilization issues that never closed after `M9` shipped.
   1. [ ] Re-test the behavior described in [#2 collapsed mobile instance controls](https://github.com/n8bar/TermiWeb/issues/2) against the shipped `0.1.1` UI on a real mobile browser.
   2. [ ] Re-test the behavior described in [#3 mobile keyboard text assistance](https://github.com/n8bar/TermiWeb/issues/3) against the shipped `0.1.1` UI on a real mobile browser with at least one mobile keyboard known to be aggressive about predictive text.
   3. [ ] For each issue, either close it with a comment pointing at the `M9` work that resolved it, or capture the residual behavior in the issue and add a remediation task to this worklist.
   4. [ ] If residual remediation tasks were added, implement and verify them before the release surface step.

3. [ ] Ship the Windows installer and the passwordless auto-start fix ([#10](https://github.com/n8bar/TermiWeb/issues/10), [#9](https://github.com/n8bar/TermiWeb/issues/9)).
   1. [ ] Confirm [the Windows-installer spec](../specs/windows-installer.md) is user-approved before implementation begins (rule `1.16`), and re-check it for scope drift at that point.
   2. [ ] Switch auto-start task registration to the `SYSTEM` principal with no stored credentials in the shared scripts, removing the Windows account password prompt entirely, and verify registration succeeds on a Windows 11 machine with Hello-only sign-in (the [#9](https://github.com/n8bar/TermiWeb/issues/9) reproduction condition).
   3. [ ] Implement installed-layout config/state resolution under ProgramData while keeping the portable zip layout's folder-relative resolution working.
   4. [ ] Author the Inno Setup script per the spec: Program Files install, app-password page, optional auto-start checkbox, install-time firewall rule, Start Menu group, and the Apps & Features uninstall entry with upgrade/preserve semantics.
   5. [ ] Extend release assembly so one staged layout emits both the installer executable and the portable zip.
   6. [ ] Add the SmartScreen "More info → Run anyway" guidance with a screenshot to the download surface and first-run docs, since the installer ships unsigned.
   7. [ ] Verify against every Acceptance Check in [the Windows-installer spec](../specs/windows-installer.md), including the clean Windows 11 VM run, then close [#9](https://github.com/n8bar/TermiWeb/issues/9) and [#10](https://github.com/n8bar/TermiWeb/issues/10). Capture any spec ambiguities discovered during implementation as edits to the spec before closing this item.

4. [ ] Implement the instance-titles spec.
   1. [ ] Re-read [the instance-titles spec](../specs/instance-titles.md) and confirm no scope drift before implementation begins.
   2. [ ] Add the protocol and state changes: a shell-title field on `SessionSummary`, a `terminal/title` client event, and a server-side broadcast path for title changes. Apply the spec's length clamp and control-character stripping on the server before broadcasting.
   3. [ ] Wire `terminal.onTitleChange` on the client to send the `terminal/title` event for the active session.
   4. [ ] Change auto-naming to assign the lowest unused positive integer without ever renaming an existing instance as a side effect of another instance's lifecycle.
   5. [ ] Update the active-instance topbar heading and the sidebar list to render the precedence rule (shell title when present and non-empty, workspace default otherwise), and apply the ellipsis-with-tooltip overflow treatment in both places.
   6. [ ] Verify against every Acceptance Check listed in [the instance-titles spec](../specs/instance-titles.md). Capture any spec ambiguities discovered during implementation as edits to the spec before closing this item.

5. [ ] Specify and implement the terminal bell behavior.
   1. [ ] Draft the bell spec under `docs/specs/` covering audio versus visual default, mobile autoplay constraints, per-instance attention indicator behavior, and any user preference surface. Pause for user review of the draft spec before implementing (rule `1.16`).
   2. [ ] After the spec is approved, implement the chosen behavior and wire `terminal.onBell` accordingly.
   3. [ ] Verify against the bell spec's Acceptance Checks on desktop and mobile browsers, including the autoplay-unlock path if audio is in scope.
   4. [ ] Close [#6](https://github.com/n8bar/TermiWeb/issues/6) once the shipped behavior matches the approved spec.

6. [ ] Refresh the release surface and ship the `0.1.2` patch release.
   1. [ ] Update release notes, `package.json` / `package-lock.json`, the website download surface, README release wording, and any packaged-install copy that becomes stale once `0.1.2` lands.
   2. [ ] Confirm screenshots and public copy still represent the shipped UI and install flow; replace anything that became misleading because of the installer, instance-titles, or bell changes.
   3. [ ] Run the local release gate: `npm run typecheck`, `npm test`, `npm run build`, `npm run build:site`, `npm run package:release` (which now also emits the installer executable).
   4. [ ] Publish the `0.1.2` GitHub release with the installer executable as the primary artifact and the portable zip as the secondary artifact, confirm the GitHub Pages deploy succeeds, and close `M10`.

	3. [ ] [#9](https://github.com/n8bar/TermiWeb/issues/9) and [#10](https://github.com/n8bar/TermiWeb/issues/10) are closed: the installer passed the [Windows-installer spec](../specs/windows-installer.md) Acceptance Checks including the clean Windows 11 Hello-only run, and no setup path asks for a Windows account password.
	4. [ ] [#7 instance titles](https://github.com/n8bar/TermiWeb/issues/7) ships in `0.1.2` against the approved [instance-titles spec](../specs/instance-titles.md), including stable numbering and overflow display.
