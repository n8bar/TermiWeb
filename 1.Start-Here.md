# Start Here

TermiWeb runs on a Windows host device. Once the host copy is running, you can use it from the host itself or from another device on the same network.

Read `DISCLAIMER.md` too. It explains the trust and deployment boundaries for `0.1`.

## Installed With The Windows Installer

The installer already collected your TermiWeb password, allowed the port through the Windows firewall on private networks, and offered before-sign-in auto-start. Your config lives in `%ProgramData%\TermiWeb\.env` and your workspace state sits beside it; nothing under `Program Files` changes at runtime.

Use the Start Menu group to open, start, restart, or stop TermiWeb and to enable or disable auto-start. Uninstall from Apps & Features; the uninstaller asks whether to remove the config and workspace state too and keeps them unless you say otherwise.

Skip ahead to section 3 to sign in.

## Unpacked From The Portable Zip

The zip keeps its config and state inside its own folder. These steps assume you unpacked it into a folder you can write to.

Run `Set Up TermiWeb.cmd` if you want TermiWeb to walk you through first-run setup, including the optional before-sign-in auto-start step. If you prefer to configure things manually, use sections 1 and 2 below.

If Windows shows a firewall prompt on first launch, allow private-network access if you want phones or other LAN devices on your network to reach the host copy. Running `scripts\set-firewall-rule.ps1` once, with elevation, creates that rule ahead of time instead.

## Auto-Start Before Sign-In

Both layouts share the same auto-start behavior. Enabling it asks Windows for elevation once. The startup task runs as the built-in `SYSTEM` account, so no Windows account password is ever requested. Shells opened on an auto-started TermiWeb run as `SYSTEM` rather than as you until you stop it and start it manually.

The installer points those shells at your own profile folder. For the zip, set `TERMIWEB_START_DIRECTORY` in `.env` to your profile path, such as `C:\Users\you`, or they open in the `SYSTEM` profile.

TermiWeb `0.1` runs elevated shells only, so Windows will also ask for elevation when you start the app manually unless it is already running at that privilege level.

## 1. Configure TermiWeb (Zip)

1. Copy `.env.example` to `.env`.
2. Set `TERMIWEB_PASSWORD` in `.env` before you start TermiWeb for the first time.
3. Leave `TERMIWEB_PORT=22443` unless you have a reason to move the packaged release off the default port.
4. Run `Enable TermiWeb Auto Start.cmd` later if you decide you want the optional before-sign-in startup task after setup.

## 2. Start The Host Copy (Zip)

1. Run `Start TermiWeb.cmd`.
2. Approve the Windows elevation prompt.
3. Wait a moment for the server to start in the background.
4. If Windows shows a firewall prompt and you want LAN access, allow private-network access for that first launch.
5. On the host device, open `http://127.0.0.1:22443`.

## 3. Sign In From The Host Device

1. Enter the TermiWeb password you chose during install or set in `.env`.
2. After login, TermiWeb should open with a seeded shared shell named `Instance 1`.

## 4. Sign In From Another Device

1. Make sure the second device is on the same network as the host device.
2. Find the host device's LAN IP address.
3. Open `http://<your-pc-lan-ip>:22443` on the second device.
4. Sign in with the same TermiWeb password.
5. Confirm that both devices show the same live `Instance 1` shell.

If `Instance 1` is already gone, use `+ New Instance` to create another shared terminal.
